# IN/OUT との差分（作業記録）

対象は許諾済み `com.graff.inout` 1.0 (3)。根拠は公開解析 `693072d`（macOS 検証 https://github.com/444yttt/shifttrack-inout-analysis/actions/runs/42381152178 ）と、パターン配置 `1da0252` / 検証記録 `ae6babe`（macOS 検証 https://github.com/444yttt/shifttrack-inout-analysis/actions/runs/42977835967 ）。元ソースではない。広告 SDK・識別子・秘密は写さない。7500円は式へその入力を入れた結果であり、画面で読んだ数字ではない。

## 選んだ日への ShiftPart（2026-11-11）

公開解析の配置 `0x1001c75ec` と、衝突が空のときだけ確定する入口（日チップ `0x10003fe54`、カレンダーのパターン行 `0x10006e04c`）を製品の保存へつなぐ。`PendingPlace` は画面の状態で、衝突があるタップは1件も挿入しない。同じ `partID` の日は足さない。秒は 0。パターンの生の `start >= end`（同じ分を含む）は終了を翌日にする。`defaultTodos` は新しい id と `done = 0` で写す。

休憩は写さない。この経路の Optional は空で、`ShiftPart.breakMinutes` も休憩選択 `0x1000e967c` も読まない。置いたシフトの休憩は 0、`breakFollowsRules` は false。編集画面の規則と、曜日ひな形が休憩分数を写す動きは変えていない。既存行の再計算はしない。

重なり `0x100016734` の式は未回収。別 part（part が無いシフトを含む）がその日にあれば、回収済みの文言「のシフトがあります」を衝突にして保留する。時刻の重なりと移動時間は使っていない。元が許す日を、この版は止めることがある。同じ part がある日は衝突にしない。

`WeekTemplate` の展開はしない。曜日のひな形 `ShiftPattern` は以前の独自実装のまま。結果の Published 先は未回収なので、既存の `WorkShift` に挿入する。成功側が読む `inout.adsRemoved` は出さない。失敗時の文は命令が当たる cstring「保存できませんでした。もう一度お試しください。」。画面で見えたことは未確認。「保存しました」はこの命令の参照先ではない。

「このまま保存」「このまま置く」はバイナリの文字列としてはある。確定処理を衝突のあとで呼ぶ命令は無いので、ボタンにはしていない。赤い「！」も、条件が未回収なので描かない。

画面の画素、Doto の適用先、アイコン、アニメーションは、画面ごとの引き渡しが無い。文字列表から採った文言（「シフトパターン」「この日に置く」「シフトパターンを作る」「パターンの名前（例：遅番）」「シフトパターンに追加」「確認が必要な日があります」「このシフトは確認が必要です」「日付をいくつか選んで、シフトパターンをまとめて置いたり、外したりします。」「その日のやることです」）は、どの枠に載るかの写真が無い。配置は今の暗い画面の中に置いた。完コピとは書かない。編集画面の同刻拒否の文だけ「開始と終了を異なる時刻にしてください。」に合わせた。時刻の大きな操作はそのまま。週のスワイプは見ている日だけを動かす。

## 画面の並び（参照の画面写真はない）

参照の実行ファイルにある `InOutTab` は list / calendar / workplaces / income / settings。タブバーの写真はないので、ピクセル一致ではない。文言「今日」「カレンダー」「勤務先」「収入」「設定」は同じ実行ファイルにある。年収の壁はタブの型には無く、収入の中から開く。週の移動文言は「左右の矢印か横にスワイプで、前後の週に移れます」。見ている日だけを動かし、保存済みシフトの日付は変えない。「黒い丸」は黒い画面では見えないので、シフトのある日はライムの点にしている。IPA に Doto フォントはある。どの文字に使われているかは写真が無いので、フォントファイルは写していない。

## 文言と型で存在が分かり、まだ製品にないもの

カレンダーアプリとリマインダーへの保存、遅刻連絡、移動時間、予定の重なりの式、勤務先の位置と地図、Google マップのリンク、ショップカード、給与明細との差、時間帯ごとの時給の境界、年収の壁の追加と通知、勤務終了の確認通知、オンボーディング。広告を消す購入と Banner 系の型はある。広告は入れない。希望・支払周期と曜日ひな形は独自実装。選んだ日への `ShiftPart` は上の再構成。画面ごとのレイアウト引き渡しはまだ無い。

## 未回収のまま

日給の `UUID.==` がどの二つのフィールドか。perDay の UUID と回数。通過後の交通は整数の一回加算までで、日数倍ではない。手当と控除。時間帯の境界。履歴が全部シフト日より後のとき。残業の「これまでの分数」が複数シフトを足すか。ゲート日付が `now` か。7500円を画面で見たこと。週オフセットを増減する命令、年収の壁の比較。「いま稼いだお給料」は別関数の文言で、ヘルプは数字が増えると書く。予定全体の金額はその増え方にならないので、その文言は付けていない。希望、週払い・日払いの入金日、`WeekTemplate` の展開、重なり検査が「のシフトがあります」以外を足す条件、配置結果の Published 先、パターン休憩をシフトへ写す命令は未回収。画面の写真が無いので、色・フォント（Doto を含む）・アイコン・アニメーション・余白は一致させていない。再構成のテストは原画面の証明ではない。

## 実機スクショを見た目の正にした画面（2026-11-11）

参照は許諾済み IN/OUT の実機 PNG 46枚（1260×2736）。公開リポジトリと PR には貼らない。勤務先の住所など個人情報が写っているため。比較に出すのは、このアプリのシミュレータ画面だけ。画素一致とは書かない。目で見た比較。

写真・イラストは IPA から取り出していない。今日の時間帯ヘッダー、勤務先登録、いつものシフトの絵は、権利上の代わりとして描いたグラデーションと図形。ロゴもビットマップではなく文字と SF Symbol で描き直した。フォントは Google Fonts の公式 Doto を、可変フォントの太さ 900・丸さ 100 でインスタンス化した `Doto-BlackRound`。IPA のフォントファイルではない。軸の端からの再構成であり、名前付きインスタンスそのものではない。

見た目で合わせたもの:

- 明るい紙色の背景、白いカード、黒いカプセルのタブバー。選択中はライムの丸に黒いアイコン、ラベルはライム。タブ名はスクショの「一覧 / カレンダー / 勤務先 / 年収 / 設定」。識別子 `tab.today` などはテストのため維持。0番のシンボル `slider.horizontal` は解析 `root.md` の確定。設定の `slider.horizontal.3` はスクショからの見た目。
- Accent は any 黒 / dark 白。起動背景は #C3FF77 のみ。画面はライトに固定。
- 今日: ワードマーク、今週のシフト、丸い曜日、大きな Doto の時刻、シフトカード、黒い「シフトを追加」、やること、「今日のお給料」の黒いカード（見込み。予定全体を「いま稼いだお給料」とは書かない）、白い「今月のお給料」。
- カレンダー: シフトのある日は黒丸にライムの数字、選択日はライム。月タイトルは Doto。
- 勤務先: 黒いカード、Doto の時給、パターンの展開。登録は 01–02–03。「写真から読み取る」は既存の端末内読み取りへつなぐ。
- 設定: 通知の黒いカードと「広告 / 非表示」。広告 SDK は入れない。目標金額など既存の設定欄は残す。
- チュートリアルは、書き起こした今日 6枚、カレンダー、勤務先、設定の各1枚だけ。UI テスト中（`-UITestingReset`）は出さない。
